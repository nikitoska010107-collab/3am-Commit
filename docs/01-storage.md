# Где хранятся данные и документы

## Коротко

| Что | Где лежит | Кто читает |
| --- | --- | --- |
| Учётные записи, компании, продукты, заявки | SQLite-файл `backend/prisma/dev.db` | только backend |
| Анкета заявки | `Application.formPayload` (JSON-строка) + `ApplicationData` | backend |
| Кредитная история | таблица `CreditReport` (+ `ExternalCheck`) | backend |
| Скоринг | `ScoringResult` + `ScoringFactor` | backend |
| Файлы документов | диск: `backend/storage/documents/<uuid>.<ext>` | backend |
| Метаданные документов | таблица `Document` | backend |
| История статусов и аудит | `StatusHistory`, `AuditLog` | backend |
| Уведомления | `Notification` | backend |

Фронтенд никогда не обращается к БД и файлам напрямую — только к REST API по JWT.

## База данных

- Драйвер: Prisma 6, провайдер `sqlite`.
- Строка подключения: `DATABASE_URL` из `backend/.env` (по умолчанию `file:./dev.db`, файл появляется в `backend/prisma/dev.db`).
- Схема: `backend/prisma/schema.prisma`, миграции — `backend/prisma/migrations`.
- Команды: `npm run prisma:migrate`, `npm run seed`, `npm run prisma:studio`.

Таблицы:

| Таблица | Назначение |
| --- | --- |
| `User` | пользователь: e-mail, bcrypt-хэш пароля, имя, роль, ссылка на компанию |
| `Company` | профиль бизнеса: ИНН, ОГРН, форма, отрасль, выручка, дата регистрации |
| `Product` | кредитные продукты: лимиты суммы и срока, ставка |
| `Application` | заявка: сумма, срок, цель, статус, `formPayload` |
| `ApplicationData` | поля анкеты и ответы на запросы банка (ключ-значение) |
| `StatusHistory` | кто и когда менял статус заявки |
| `ScoringResult`, `ScoringFactor` | результат скоринга и объяснение по каждому фактору |
| `Offer` | предложение банка (стандартное или контрпредложение) |
| `Decision` | решение банка + причина |
| `ExternalCheck` | обращения к внешним источникам (БКИ, ЕГРЮЛ, ФНС) |
| `CreditReport` | сохранённый отчёт кредитной истории |
| `Document` | метаданные загруженного файла |
| `Notification` | уведомления клиента |
| `AuditLog` | журнал действий по заявке и сущностям |

JSON-поля хранятся строками (`String`), потому что SQLite в Prisma не поддерживает `Json`/enum. Разбор — в сервисах, наружу отдаются нормальные объекты.

### Чувствительные данные

- Пароли — только bcrypt-хэш (стоимость 10), открытый пароль нигде не сохраняется.
- В `AuditLog` и `Notification` не попадают пароли и полные номера документов.
- `rawPayload` сырого ответа БКИ хранится для воспроизводимости; наружу через API отдаются только нормализованные поля.

## Документы

- Каталог: `DOCUMENT_STORAGE_PATH` (по умолчанию `backend/storage/documents`). Каталог в `.gitignore`.
- Имя на диске — `randomUUID()` + исходное расширение, поэтому имя пользователя не участвует в пути (нет path traversal).
- В `Document` пишутся: исходное имя, имя на диске, MIME, размер, вид, SHA-256, полный путь, автор, заявка, дата.
- Ограничения загрузки: 20 МБ на файл, до 10 файлов в одном запросе (`@fastify/multipart`).
- Скачивание — только через `GET /api/documents/:id` с проверкой прав; публичных URL нет.
- Удаление — `DELETE /api/documents/:id` (автор или сотрудник банка), файл и запись удаляются.
- Виды документов: `FINANCIAL_STATEMENT`, `BANK_STATEMENT`, `REGISTRATION_DOCUMENT`, `OTHER`.

## Разграничение доступа

- `CLIENT` видит только свои заявки и документы своей компании; чужие запросы получают `403`.
- `UNDERWRITER` и `ADMIN` видят все заявки, историю, аудит и могут скачивать документы.
- Проверка выполняется на каждом эндпоинте (`ApplicationsService.getAccessible`, guards), а не только на фронте.

## Переезд на прод

1. Поменять провайдер в `schema.prisma` на `postgresql` и `DATABASE_URL`.
2. Пересоздать миграции, выполнить seed/перенос данных.
3. Файлы вынести в S3-совместимое хранилище: `DocumentsService.save/readStream` — единственное место, которое знает про диск.
4. Секреты (`JWT_SECRET`, строка БД) — только через переменные окружения, не в репозитории.
