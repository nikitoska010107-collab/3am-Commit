# Авторизация и регистрация

## Схема

- Аутентификация: JWT (HS256), срок жизни `JWT_EXPIRES_IN` (по умолчанию `1d`), секрет `JWT_SECRET`.
- Пароли: `bcryptjs`, cost 10. Открытый пароль не логируется и не хранится.
- Токен передаётся заголовком `Authorization: Bearer <token>`.
- Глобальный `JwtAuthGuard` закрывает все эндпоинты; открыты только помеченные `@Public()`.
- Роли проверяет `RolesGuard` по метаданным `@Roles(...)`.

Полезная нагрузка токена:

```json
{
  "sub": "<userId>",
  "email": "client.approve@demo.local",
  "name": "Анна Смирнова",
  "role": "CLIENT",
  "companyId": "<companyId>"
}
```

## Эндпоинты

| Метод | Путь | Доступ | Что делает |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | публично | создаёт компанию и пользователя с ролью `CLIENT`, возвращает токен |
| `POST` | `/api/auth/login` | публично | проверяет пароль, возвращает токен и профиль |
| `GET` | `/api/auth/me` | по токену | профиль текущего пользователя вместе с компанией |

Регистрация принимает e-mail, пароль (мин. 8), имя и блок `company` (название, ИНН, ОГРН, правовая форма, отрасль, выручка, дата регистрации). Компания создаётся в той же операции; ИНН не уникален на уровне API — при повторной регистрации с тем же ИНН создастся вторая компания (для демо допустимо, на проде нужна проверка ЕГРЮЛ).

Ответ `register`/`login`:

```json
{
  "accessToken": "eyJ...",
  "tokenType": "Bearer",
  "expiresIn": 86400,
  "user": {
    "id": "...",
    "email": "client.approve@demo.local",
    "name": "Анна Смирнова",
    "role": "CLIENT",
    "company": { "id": "...", "inn": "7701234567", "name": "ООО «Восход»", "...": "..." }
  }
}
```

## Роли

| Роль | Что может |
| --- | --- |
| `CLIENT` | свои заявки: создать черновик, править, отправить, отменить, принять предложение, ответить на запрос данных, загрузить документы, читать уведомления |
| `UNDERWRITER` | очередь заявок, кредитная история, скоринг, решение, подписание и выдача (симуляция), все документы |
| `ADMIN` | то же, что `UNDERWRITER`, плюс управление продуктами |

## Демо-доступы (после `npm run seed`)

| E-mail | Пароль | Роль | Сценарий |
| --- | --- | --- | --- |
| `client.approve@demo.local` | `demo` | `CLIENT` | хорошая история, одобрение |
| `client.counter@demo.local` | `demo` | `CLIENT` | средняя история, контрпредложение |
| `client.reject@demo.local` | `demo` | `CLIENT` | банкротство, отказ |
| `underwriter@demo.local` | `demo` | `UNDERWRITER` | кабинет банка |
| `admin@demo.local` | `demo` | `ADMIN` | администрирование |

## Ошибки

| Код | HTTP | Когда |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | нет токена, токен просрочен или неверный пароль |
| `FORBIDDEN` | 403 | роль не подходит или клиент запрашивает чужой объект |
| `CONFLICT` | 409 | e-mail уже зарегистрирован |

Тело ошибки всегда `{ "code": "...", "message": "...", "details": ... }`.

## Ограничения текущей версии

- Нет refresh-токена и выхода на сервере: клиент удаляет токен сам, срок жизни короткий.
- Нет подтверждения e-mail и восстановления пароля — вне сценария хакатона.
- Нет rate limiting на `/auth/login` — добавить перед публичным запуском.
- `JWT_SECRET` в dev-примере — учебный; на проде обязателен свой секрет из окружения.
