# Отчёт: что сделано

Дата: 22.10.2026. Ветка: `BACKand`. Автор: Кирилл (backend).

## Итог

Поднят рабочий backend умного кредитного кабинета: от регистрации предпринимателя до выдачи кредита в симуляции. Реализованы все четыре задачи дня — хранение данных и документов, авторизация, заявки с валидацией, кредитная история. Дополнительно закрыт контракт скоринга для Влада и выгружен OpenAPI.

## Что реализовано

### 1. Хранение данных и документов

- Prisma-схема на 15 моделей: пользователи, компании, продукты, заявки, анкета, статусы, скоринг, факторы, предложения, решения, внешние проверки, кредитные отчёты, документы, уведомления, аудит.
- SQLite `backend/prisma/dev.db`, миграция `20261022145330_init`.
- Файлы документов — `backend/storage/documents/<uuid>.<ext>`, метаданные и SHA-256 в БД, лимит 20 МБ, скачивание только через API с проверкой прав.
- Разграничение доступа: клиент видит только свои объекты, банк — все.

### 2. Авторизация

- Регистрация создаёт компанию и пользователя с ролью `CLIENT`.
- Вход по e-mail и паролю, JWT (HS256, срок из env), bcrypt cost 10.
- Глобальные `JwtAuthGuard` и `RolesGuard`, публичные маршруты через `@Public()`.
- `GET /api/auth/me` с профилем компании.
- Seed: 5 демо-пользователей с паролем `demo`, включая три сценария (одобрение, контрпредложение, отказ).

### 3. Заявки

- Создание черновика, редактирование, отправка, отзыв, ответ на запрос данных, принятие предложения.
- Шесть слоёв валидации: DTO (class-validator), лимиты продукта, полнота анкеты при отправке, статус, машина переходов, права доступа.
- 12 статусов и явная таблица разрешённых переходов; переходы делает только backend.
- Очередь банка, скоринг, решения (одобрение / отказ / контрпредложение / запрос данных), подписание и выдача.
- Уведомления клиенту и аудит каждого действия.

### 4. Кредитная история

- Мок БКИ с детерминированными профилями по ИНН (780 / 645 / 515) и fallback для остальных.
- `refresh` сохраняет снимок `CreditReport` и `ExternalCheck`, пишет аудит.
- Отчёт используется скорингом; сырые данные доступны только банку.
- Эндпоинты по заявке и по компании, плюс отладочный `/api/mock/bki/:companyId`.

### 5. Скоринг и контракт

- Интерфейс `ScoringProvider` + токен `SCORING_PROVIDER`: замена правила-базового провайдера на ML-модель без правок сервиса.
- 6 факторов с весами и обязательным объяснением, итог 0..100 и риск `LOW/MEDIUM/HIGH`.
- Контракт для Влада — `docs/05-scoring-contract.md`.
- OpenAPI выгружается командой `npm run openapi:export` в `openapi.yaml` и `openapi.json` (33 маршрута).

## Принятые решения

- Backend: NestJS + Fastify + TypeScript; ORM Prisma; SQLite сейчас, Postgres на проде.
- Docker не используется на этом этапе.
- Документы — файловая система + метаданные в БД (позже S3).
- Моки внешних источников вместо платных API (требование кейса).
- JWT без refresh-токена: сценарий хакатона не требует.

## Ограничения и риски

- Нет rate limiting на логине, подтверждения e-mail и восстановления пароля.
- ИНН компании не уникален на уровне API — на проде нужна проверка ЕГРЮЛ.
- Скоринг — правила, не ML; заменяется через `SCORING_PROVIDER`.
- Фронтенд не подключён к API в этой ветке: контракт готов, интеграция за фронтенд-разработчиком.
- Ветка `BACKand` ещё не запушена в GitHub — нужен PAT или ручной push.
